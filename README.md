# 长篇小说创作系统 v5.3 使用手册

## 这是什么
人在回路的多会话协作小说创作系统，通过4个长期会话+1个临时会话配合，解决现实主义题材创作中的真实性、人物一致性、审稿放水、LLM编事实等问题。

---

## 第一步：启动4个长期会话

在Trae中开3个新会话（加上当前主控会话共4个），每个会话只做一件事，不要混用。

### 会话1：主控会话（就是你现在在用的这个）
- 角色：总编助理，唯一和你直接对话的入口
- 启动：本会话启动后，第一条消息发：
  ```
  读 /workspace/prompts/master.md，你现在是主控会话。
  ```
- 职责：你只需要和这个会话说话，它负责告诉你下一步给其他会话发什么、检查质量、管理文件。

### 会话2：写稿会话
- 角色：创作端，负责所有写的活（选题、策划、提纲、正文）
- 启动：新开一个Trae会话，第一条消息发：
  ```
  读 /workspace/prompts/writer.md，你现在是写稿会话，负责小说创作。
  ```
- 长期开着，不要关。

### 会话3：审稿会话
- 角色：独立第三方审稿人，只挑错，不写东西
- 启动：新开一个Trae会话，第一条消息发：
  ```
  读 /workspace/prompts/reviewer.md，你现在是独立审稿会话，只负责审稿挑错。
  ```
- 长期开着，不要关。**绝对不要在这个会话里说"帮我写个东西"，它只审稿。**

### 会话4：调研会话
- 角色：事实调研员，负责找真实信息、验证来源、补facts
- 启动：新开一个Trae会话，第一条消息发：
  ```
  读 /workspace/prompts/researcher.md，你现在是调研会话，负责事实调研和来源验证。
  ```
- 长期开着，不要关。**绝对不要在这个会话里写小说内容。**

## 临时会话：风格蒸馏（只在开新书需要模仿作者风格时用）
- 什么时候用：你想模仿某本小说/某个作者的风格开新书
- 启动：新开一个Trae会话，第一条消息发：
  ```
  读 /workspace/prompts/distiller.md，现在做作者风格蒸馏。作者名：<作者slug>，样本文件路径：<txt/epub路径>
  ```
- 做完之后，这个会话可以关掉，蒸馏好的风格规则会保存在`authors/<author_slug>/`目录里。

## 日常工作流（你只需要和主控会话说话）

### 完整流程示例：开一本新小说到写完第一章

1. **你对主控会话说**："我想新开一本现实主义题材小说，方向是边境木材走私，模仿云峰的风格"
2. **主控会告诉你**：
   - "请打开蒸馏会话，发以下消息：..."（如果需要蒸馏）
   - 或者"请发给调研会话：..."（开始做热点调研）
3. **你按照主控说的，把指定消息复制粘贴到对应会话**
4. **对应会话产出文件后，你告诉主控**："写稿/调研/审稿会话已经产出了，文件在xxx"
5. **主控会检查文件**：跑检查脚本、抽样验证来源，不合格会告诉你"打回，告诉xx会话重改：xxx"，合格会告诉你下一步发给谁
6. **重复这个循环**：主控调度→你传消息→会话产出→主控检查→下一步，直到内容定稿

### 日常写作流程简化版
```
你说"写下一批提纲/写下一章"
  ↓
主控检查facts是否齐全→缺了告诉你发给调研会话补
  ↓
facts齐全→主控告诉你发给写稿会话写（写稿会话会先做场景检查，缺事实会停下要调研）
  ↓
写稿会话写完→主控检查脚本→告诉你发给审稿会话审
  ↓
审稿会话审完→主控检查审稿质量→把问题和稿子给你看
  ↓
你说"通过"或者"改xxx"→主控安排修改/定稿
  ↓
定稿后你说"commit/push"，主控才执行Git操作
```

## 你需要做的事只有三件
1. **和主控说话，告诉它你想做什么**（开新书、写、改、不满意哪里、commit/push）
2. **按照主控的指示，把消息复制粘贴到对应会话**（主控会给你写好完整的消息，你直接复制就行）
3. **对结果拍板**：内容好不好、改不改、通过不通过，你说了算

其他所有事（流程调度、检查脚本、facts核对、抽样验证、文件更新、进度记录）都是主控的事，你不用管。

## 会话之间的规则（非常重要，不要破坏）
1. **会话不要混用**：写稿会话只写稿，审稿会话只审稿，调研会话只调研，不要让审稿会话帮你写东西，不要让写稿会话自己审稿
2. **只传文件路径**：你只需要传**文件路径**，所有内容都通过共享的/workspace目录传递，不要大段复制粘贴内容给其他会话
3. **审稿会话保持中立**：发给审稿会话的消息里，不要说"这是我们刚写的，麻烦看看"，就说"审这个文件：<路径>，审稿类型：<xxx>"（主控会给你写好标准消息，直接复制就行）
4. **会话放水就重置**：如果某个会话连续2次产出不合格、审稿放水、写稿编事实，告诉主控，主控会建议你重置该会话（重新开一个，重新发启动消息）
5. **所有文件都在/workspace里**：所有会话看到的都是同一份本地文件，A会话改了文件，B会话重新Read就能拿到最新版，不需要走GitHub
6. **会话重置后不会丢进度**：每个小说目录下有`progress.md`记录进度，主控每次操作前会读，会话重启后看progress.md就知道做到哪了

## 异常处理
| 问题 | 怎么办 |
|------|--------|
| 写稿会话说"需要补调研" | 告诉主控，主控会给你调研会话的消息，你传过去就行 |
| 审稿会话说"整体不错没什么问题"且没附核对过程 | 告诉主控，主控会判断是不是放水，放水会让你打回重审 |
| 你对内容不满意 | 直接跟主控说哪里不满意，主控会做根因诊断（是设定错了、facts错了、还是文字问题），告诉你怎么改 |
| 改坏了想回滚 | 告诉主控"回滚到xxx标签"，主控会用Git回滚（前提是你之前让主控打过标签） |
| 某个会话开始胡说八道/忘规则 | 关掉它，重新开一个会话，重新发启动消息 |
| 两个会话意见矛盾 | 告诉主控，主控会把矛盾点列出来让你仲裁 |
| 需要提交代码到GitHub | 对主控说"commit并push"或者"push到main"，主控才会执行Git操作 |

## Git规则
**主控不会主动做任何Git操作（包括commit）**。只有你明确说"commit""提交""push""打标签"时，主控才会执行。

常用Git指令你可以直接对主控说：
- "commit"：本地commit
- "push"：commit+push到main
- "打标签xxx"：打标签
- "回滚到xxx"：git reset到对应标签

## 文件在哪里
所有东西都在`/workspace/`下：
- 系统总览：`/workspace/SYSTEM.md`
- 各会话Prompt：`/workspace/prompts/`
- 检查脚本：`/workspace/tools/`
- 作者风格库：`/workspace/authors/`
- 你的小说：`/workspace/work/<小说slug>/`
  - 进度记录：`progress.md`
  - 核心设定：`bible/`（facts.md在这）
  - 提纲：`batch_plans/`
  - 正文：`chapters/`
  - 审稿意见：`reviews/`
