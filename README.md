# 长篇小说创作系统 v5.4 使用手册

## 这是什么
人在回路的多会话协作小说创作系统。核心模式：**定骨不定路，事件驱动**——开书定死主角欲望、困境、人物关系等"骨头"，不预设远期剧情；每章写前查真实事件，用真实事件推动故事，主角在事件中主动选择，故事自然生长。解决现实主义题材真实性、人物一致性、审稿放水、LLM编事实等问题。

---

## 第一步：启动4个长期会话

在Trae中开3个新会话（加上当前主控会话共4个），每个会话只做一件事。

### 会话1：主控会话
- 角色：总编助理，唯一和你直接对话的入口
- 启动：第一条消息发：
  ```
  读 /workspace/prompts/master.md，你现在是主控会话。
  ```

### 会话2：写稿会话
- 角色：创作端，选题、开书定骨、写正文、更新状态
- 启动：
  ```
  读 /workspace/prompts/writer.md，你现在是写稿会话。
  ```

### 会话3：审稿会话
- 角色：独立第三方审稿人，只挑错
- 启动：
  ```
  读 /workspace/prompts/reviewer.md，你现在是独立审稿会话。
  ```
- **绝对不要在这个会话写东西，它只审稿。**

### 会话4：调研会话
- 角色：事实调研员，热点调研、滚动事件调研、事实补全、来源验证
- 启动：
  ```
  读 /workspace/prompts/researcher.md，你现在是调研会话。
  ```
- **绝对不要在这个会话写小说内容。**

## 日常工作流

### 开新书流程
1. 你对主控说开新书写什么方向（默认调研热点改编）
2. 主控调度：调研热点→写稿做选题→审稿→你选方案
3. 开书定骨：写稿做bible目录（facts+人物+core_bones核心骨架+前3章触发事件）→审稿→你确认
4. 之后进入逐章循环

### 逐章写作循环（核心流程）
```
第N章定稿
  ↓
主控派调研：查故事时间窗内真实事件，更新event_pool
  ↓
你和主控一起选1-2个直接影响主角的事件作为下一章触发
  ↓
主控告诉你发给写稿会话写第N+1章
  ↓
写稿写完→主控检查（脚本+主动性+钩子+状态更新）
  ↓
发给审稿会话审
  ↓
主控检查审稿质量→你拍板通过/修改
  ↓
进入下一章循环
```

### 修改
直接跟主控说哪里不满意，主控做根因诊断告诉你怎么改。

## 你只做三件事
1. 和主控说话，告诉它你想做什么
2. 按主控指示复制消息到对应会话，产出后告诉主控文件路径
3. 对结果拍板：通过/修改/选哪个方案/commit/push

其他事（流程调度、事件筛选、检查脚本、facts核对、节奏把控、抽样验证）都是主控的事。

---

## 会话规则
1. **不混用**：写稿只写、审稿只审、调研只调研
2. **只传文件路径**：不传内容，所有会话共享`/workspace`本地目录
3. **审稿中立**：发给审稿的消息不说"这是我们写的"，只说"审这个文件"
4. **放水就重置**：会话连续2次不合格，关掉重开
5. **进度不丢**：每本小说有`progress.md`，主控每次操作前后读写，会话重启不丢进度

---

## 核心概念
- **core_bones.md**：核心骨架——主角核心欲望（一句话）、初始困境、核心人物关系、第一卷方向（<200字）。开书定死，不轻易改。
- **event_pool.md**：事件池——调研会话持续更新真实事件，按"直接影响/间接影响/背景噪音"分类，写稿必读。
- **facts.md**：硬事实数据表——只记内行一看就假的和前后容易矛盾的事实，覆盖6大类。
- **定骨不定路**：骨头（欲望/困境/方向）定死，路（具体发生什么）由真实事件驱动，不预设远期剧情。
- **事件出题，人物答题**：真实事件发生了，主角以他的性格主动选择应对，选择推动故事。

---

## Git规则
**主控不主动做任何Git操作**。你说"commit"才commit，说"push"才push，说"打标签"才打标签，说"回滚"才回滚。

---

## 异常处理
| 问题 | 怎么办 |
|------|--------|
| 写稿说需要补调研 | 告诉主控，它给你调研消息 |
| 审稿说"没问题"但没附核对过程 | 告诉主控，打回重审 |
| 你不满意 | 直接说哪里不满意，主控做根因诊断 |
| 改坏了 | 说"回滚到xxx标签" |
| 会话胡说八道/忘规则 | 关掉重开，重新发启动消息 |
| 最近节奏太拖 | 主控会主动提醒你需要一个反转/爽点事件 |
