# 长篇小说创作系统 v5.9 使用手册

## 这是什么
人在回路的多会话协作小说创作系统。核心模式：**定骨不定路，大事件定阶段，人物自然生长**——开书定死主角欲望、困境、人物关系等"骨头"，不预设远期剧情；每个写作阶段（10-20章）开始前，调研故事时间窗内能改变整个阶段走向的真实大事件，用1-2个大事件作为这一阶段的外部压力和核心冲突；阶段内章节顺着人物性格、目标、关系和选择自然生长，小细节、行业日常、社会背景音随手填充真实感，不每章硬找事件。主角在阶段压力下主动选择、渐进变化，阶段收尾时发生质变自然引出下一阶段。

---

## 第一步：启动4个长期会话

在Trae中开3个新会话（加上当前主控会话共4个），每个会话只做一件事。

### 会话1：主控会话
- 角色：总编助理，唯一和你直接对话的入口
- 启动：第一条消息发：
  ```
  读 /workspace/prompts/master.md，你现在是主控会话。
  ```

### 会话2：写稿会话
- 角色：创作端，选题、开书定骨、阶段思考、章节小思考、写正文、更新状态
- 启动：
  ```
  读 /workspace/prompts/writer.md，你现在是写稿会话。
  ```

### 会话3：审稿会话
- 角色：独立第三方审稿人，只挑错（八维度：事实/主动性/人物/节奏/事件融入/内在状态/阶段连贯/文笔）
- 启动：
  ```
  读 /workspace/prompts/reviewer.md，你现在是独立审稿会话。
  ```
- **绝对不要在这个会话写东西，它只审稿。**

### 会话4：调研会话
- 角色：事实调研员，热点调研、阶段大事件调研、事实补全、来源验证
- 启动：
  ```
  读 /workspace/prompts/researcher.md，你现在是调研会话。
  ```
- **绝对不要在这个会话写小说内容。**

## 临时会话：风格蒸馏
模仿某作者风格开新书时用，做完关掉：
```
读 /workspace/prompts/distiller.md，做风格蒸馏。作者：<slug>，样本：<路径>
```
支持txt/epub/mobi/md格式（mobi用Calibre自动转文本），产出保存在`authors/<author_slug>/`。

## 日常工作流

### 开新书流程
1. 你对主控说开新书写什么方向（默认调研热点改编）
2. 主控调度：调研热点→写稿做选题→主控检查来源质量→你直接选定方案（选题不审）
3. 开书定骨：写稿做bible目录（facts+人物+core_bones核心骨架+story_threads初始线索+world_state初始状态+event_pool空池+current_stage初始化）→**独立审稿**→你确认
4. 总编确认后进入第一个阶段规划

### 核心工作流：阶段规划 → 阶段内逐章写作 → 阶段收尾 → 下一阶段

```
开书定骨完成
  ↓
【阶段规划】（每10-20章一次）
  主控读当前状态 → 派调研查这一阶段时间窗内真实大事件 → 更新event_pool
  ↓
  你和主控一起选阶段核心大事件，定：主角本阶段核心目标、核心冲突、大概多少章、阶段结束到哪里
  ↓
  派写稿做阶段思考（事件怎么传导、主角行动线、推进哪些线索、内在变化方向、收尾大概方向）
  ↓
  你确认阶段思考 → 更新current_stage.md
  ↓
【阶段内逐章写作】（日常流程，一章一章写）
  派写稿写本章：章节小思考（推进什么/主动选择/小变化/钩子）→ 直接写正文 → 更新所有状态
  ↓
  主控检查（脚本+硬指标+状态更新+阶段连贯）→ 审稿审正文（八维度）→ 你拍板
  ↓
  每5章小检查：节奏？爽点？人物变化？
  ↓
  判断是否到阶段收尾：核心冲突解决/质变了吗？
  ├─ 没到 → 继续写下一章
  └─ 到了 → 进入阶段收尾
  ↓
【阶段收尾】
  派写稿写收尾章 → 检查（冲突有结果？外质变？内在落点？引出下阶段？）→ 审稿
  ↓
  你确认 → 归档current_stage为stage_N_summary.md → 标记event_pool事件已融入 → 更新progress
  ↓
进入下一阶段规划
```

### 修改
直接跟主控说哪里不满意，主控做根因诊断告诉你怎么改。

## 你只做三件事
1. 和主控说话，告诉它你想做什么
2. 按主控指示复制消息到对应会话，产出后告诉主控文件路径
3. 对结果拍板：通过/修改/选哪个方案/确认阶段思考方向/commit/push

其他事（流程调度、阶段事件筛选、检查脚本、facts核对、节奏把控、阶段收尾判断、抽样验证）都是主控的事。

---

## 会话规则
1. **不混用**：写稿只写、审稿只审、调研只调研
2. **只传文件路径**：不传内容，所有会话共享`/workspace`本地目录
3. **审稿中立**：发给审稿的消息不说"这是我们写的"，只说"审这个文件"
4. **放水就重置**：会话连续2次不合格，关掉重开
5. **进度不丢**：每本小说有`progress.md`和`current_stage.md`，主控每次操作前后读写，会话重启不丢进度

## 核心概念
- **core_bones.md**：核心骨架——主角核心欲望（一句话）、初始困境、核心人物关系、第一卷方向（<200字）。开书定死，不轻易改。
- **current_stage.md**：当前阶段状态——第几阶段、核心目标、核心大事件、核心冲突、故事时间范围、进度。阶段开始时写，阶段结束后归档。
- **event_pool.md**：事件池——只放阶段级大事件，阶段开始前调研更新，按"当前阶段核心/待触发/已融入/背景音"分类。章节小细节不进池子，写稿自然加。
- **story_threads.md**：故事线索——追踪所有悬而未决/推进中/已收束的线索，选阶段大事件时优先引爆已有线索。
- **world_state.md**：世界状态——分"外在处境"（含当前阶段核心目标）和"内在状态"两部分，每章更新，追踪主角底线移动和认知变化。
- **facts.md**：硬事实数据表——只记内行一看就假的和前后容易矛盾的事实，覆盖6大类。
- **定骨不定路**：骨头（欲望/困境/方向）定死，路（具体发生什么）由阶段大事件+人物选择自然生长，不预设远期剧情。
- **大事件定阶段，小细节自然填**：每个阶段1-2个真实大事件定核心冲突压力，阶段内不每章找新事件，人物日常闲聊里自然带行业细节和背景音。
- **事件通过社交网络传入**：主角从朋友、同行、亲眼目睹得知事件，绝不刷新闻看到。大事件也是一层一层传过来，主角一开始可能只知道一点。
- **人物是发动机，不是事件棋子**：主角有自己的阶段目标和行动线，事件只是改变他做选择时的环境和筹码，不是事件说什么他就做什么。
- **阶段方向是大方向不是锁死**：写飞了自然偏离也允许，跟着人物走，主控和审稿会判断是否需要调整。

## Git规则
**主控不主动做任何Git操作**。你说"commit"才commit，说"push"才push，说"打标签"才打标签，说"回滚"才回滚。

---

## 异常处理
| 问题 | 怎么办 |
|------|--------|
| 写稿说需要补调研 | 告诉主控，它给你调研消息 |
| 审稿说"没问题"但没附核对过程 | 告诉主控，打回重审 |
| 你不满意 | 直接说哪里不满意，主控做根因诊断 |
| 改坏了 | 说"回滚到xxx标签" |
| 会话胡说八道/忘规则 | 关掉重开，重新发启动消息 |
| 最近节奏太拖 | 主控会主动提醒你章节内可以加小转折 |
| 连续5章人物没成长/赌注没升级 | 主控会主动提醒你 |
| 写稿频繁偏离阶段方向 | 主控会提醒你考虑微调阶段方向 |
| 核心冲突提前解决了 | 不要硬拖章节数，自然收尾进入下一阶段 |
| 找不到合适的阶段大事件 | 用人际冲突/对手行动/已有线索升级做阶段核心，不要硬塞事件 |

## 文件位置
- 系统总览：`/workspace/SYSTEM.md`
- 会话Prompt：`/workspace/prompts/`
- 检查脚本：`/workspace/tools/`
- 作者风格：`/workspace/authors/`
- 小说工作区：`/workspace/work/<slug>/`
  - 核心骨架：`bible/core_bones.md`
  - 当前阶段：`bible/current_stage.md`
  - 事件池（阶段级大事件）：`bible/event_pool.md`
  - 故事线索：`bible/story_threads.md`
  - 世界状态（外在+内在）：`bible/world_state.md`
  - 阶段归档：`bible/stage_<N>_summary.md`
  - 事实数据：`bible/facts.md`
  - 人物状态：`bible/character_state.md`
  - 正文：`chapters/`
  - 审稿：`reviews/`

**注意**：
- ❌ 不建`events/`目录，大事件调研直接更新event_pool
- ❌ 不建`chapter_plans/`目录，章节小思考在写稿输出里完成
- ❌ 不建单独的`stage_plans/`目录，阶段思考确认后写入current_stage.md
- ✅ 阶段结束存一个简单的stage_N_summary.md归档，不丢进度
- ✅ 章节小细节、行业日常、背景音不要求调研，写稿根据行业真实感自然填充
