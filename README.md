# 长篇小说创作系统 v5.5 使用手册

## 这是什么
人在回路的多会话协作小说创作系统。核心模式：**定骨不定路，事件驱动，人物变化**——开书定死主角欲望、困境、人物关系等"骨头"，不预设远期剧情；每章写前查真实事件，优先引爆已有线索，事件通过人物社交网络传入，主角在应对中主动选择并发生内在变化，故事自然生长。解决现实主义题材真实性、人物一致性、审稿放水、LLM编事实、主角被动、人物不成长等问题。

---

## 第一步：启动4个长期会话

在Trae中开3个新会话（加上当前主控会话共4个），每个会话只做一件事。

### 会话1：主控会话
- 角色：总编助理，唯一和你直接对话的入口
- 启动：第一条消息发：
  ```
  读 /workspace/prompts/master.md，你现在是主控会话。
  ```

### 会话2：写稿会话
- 角色：创作端，选题、开书定骨、章节思考、写正文、更新状态
- 启动：
  ```
  读 /workspace/prompts/writer.md，你现在是写稿会话。
  ```

### 会话3：审稿会话
- 角色：独立第三方审稿人，只挑错（七维度：事实/主动性/人物/节奏/事件融入/内在状态/文笔）
- 启动：
  ```
  读 /workspace/prompts/reviewer.md，你现在是独立审稿会话。
  ```
- **绝对不要在这个会话写东西，它只审稿。**

### 会话4：调研会话
- 角色：事实调研员，热点调研、滚动事件调研、事实补全、来源验证
- 启动：
  ```
  读 /workspace/prompts/researcher.md，你现在是调研会话。
  ```
- **绝对不要在这个会话写小说内容。**

## 日常工作流

### 开新书流程
1. 你对主控说开新书写什么方向（默认调研热点改编）
2. 主控调度：调研热点→写稿做选题→审稿→你选方案
3. 开书定骨：写稿做bible目录（facts+人物+core_bones核心骨架+story_threads初始线索+world_state初始状态+event_pool初始事件+前3章触发事件思考）→审稿→你确认
4. 之后进入逐章循环

### 逐章写作循环（核心流程）
```
第N章定稿
  ↓
主控派调研：查故事时间窗内真实事件，直接更新event_pool（不建单独文件）
  ↓
你和主控一起选事件：优先能引爆story_threads已有线索的，其次能推动主角内在变化的
  ↓
派写稿：先列"本章思考"（核心事件+内在变化方向+涉及线索+传入方式+主动选择+钩子）
  ↓
你确认思考方向没问题→写稿写正文→更新所有状态文件（含world_state内在状态+story_threads）
  ↓
主控检查（脚本+主动性+钩子+事件融入+内在状态+状态更新）
  ↓
发给审稿会话审（七维度全查）
  ↓
主控检查审稿质量→你拍板通过/修改
  ↓
每5章主控自动做一次升级审视：赌注升级了吗？人物变化了吗？
  ↓
进入下一章循环
```

### 修改
直接跟主控说哪里不满意，主控做根因诊断告诉你怎么改。

## 你只做三件事
1. 和主控说话，告诉它你想做什么
2. 按主控指示复制消息到对应会话，产出后告诉主控文件路径
3. 对结果拍板：通过/修改/选哪个方案/commit/push/确认章节思考方向

其他事（流程调度、事件筛选、检查脚本、facts核对、节奏把控、成长审视、抽样验证）都是主控的事。

---

## 会话规则
1. **不混用**：写稿只写、审稿只审、调研只调研
2. **只传文件路径**：不传内容，所有会话共享`/workspace`本地目录
3. **审稿中立**：发给审稿的消息不说"这是我们写的"，只说"审这个文件"
4. **放水就重置**：会话连续2次不合格，关掉重开
5. **进度不丢**：每本小说有`progress.md`，主控每次操作前后读写，会话重启不丢进度

## 核心概念
- **core_bones.md**：核心骨架——主角核心欲望（一句话）、初始困境、核心人物关系、第一卷方向（<200字）。开书定死，不轻易改。
- **event_pool.md**：事件池——调研直接更新，按"直接影响/间接影响/背景噪音"分类，标注状态（待触发/已融入/已过期），写稿必读。
- **story_threads.md**：故事线索——追踪所有悬而未决/推进中/已收束的线索，选事件时优先引爆已有线索。
- **world_state.md**：世界状态——分"外在处境"和"内在状态"两部分，每章更新，追踪主角底线移动和认知变化。
- **facts.md**：硬事实数据表——只记内行一看就假的和前后容易矛盾的事实，覆盖6大类。
- **定骨不定路**：骨头（欲望/困境/方向）定死，路（具体发生什么）由真实事件驱动，不预设远期剧情。
- **事件通过社交网络传入**：主角从朋友、同行、亲眼目睹得知事件，绝不刷新闻看到。
- **先问内心变化**：写每章第一个问题是"主角内心会发生什么变化"，事件是为了推动人物成长。
- **优先引爆已有线索**：不随便开新线，新事件要勾着旧悬念走。

## Git规则
**主控不主动做任何Git操作**。你说"commit"才commit，说"push"才push，说"打标签"才打标签，说"回滚"才回滚。

---

## 异常处理
| 问题 | 怎么办 |
|------|--------|
| 写稿说需要补调研 | 告诉主控，它给你调研消息 |
| 审稿说"没问题"但没附核对过程 | 告诉主控，打回重审 |
| 你不满意 | 直接说哪里不满意，主控做根因诊断 |
| 改坏了 | 说"回滚到xxx标签" |
| 会话胡说八道/忘规则 | 关掉重开，重新发启动消息 |
| 最近节奏太拖 | 主控会主动提醒你需要一个反转/爽点事件 |
| 连续5章人物没成长/赌注没升级 | 主控会主动提醒你需要一个考验底线的事件 |

## 文件位置
- 系统总览：`/workspace/SYSTEM.md`
- 会话Prompt：`/workspace/prompts/`
- 检查脚本：`/workspace/tools/`
- 作者风格：`/workspace/authors/`
- 小说工作区：`/workspace/work/<slug>/`
  - 核心骨架：`bible/core_bones.md`
  - 事件池：`bible/event_pool.md`
  - 故事线索：`bible/story_threads.md`
  - 世界状态（外在+内在）：`bible/world_state.md`
  - 事实数据：`bible/facts.md`
  - 人物状态：`bible/character_state.md`
  - 正文：`chapters/`
  - 审稿：`reviews/`

**注意**：不建`events/`和`chapter_plans/`目录，事件直接更新event_pool，章节思考在写稿输出中完成，避免文件臃肿。
